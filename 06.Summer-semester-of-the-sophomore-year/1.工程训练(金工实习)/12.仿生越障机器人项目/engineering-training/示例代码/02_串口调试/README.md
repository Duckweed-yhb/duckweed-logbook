# 02 串口调试

## 本例程学什么

本例程用最少的代码说明串口调试的基本用法。完成后，你应该能做到：

1. 打开 Arduino IDE 的串口监视器。
2. 设置和代码一致的波特率。
3. 看懂 `Serial.print()`、`Serial.println()` 和 `millis()` 的输出。
4. 用串口输出判断程序是否正在运行。

串口是后续排查舵机、电机和网页控制问题的主要工具。硬件没有动作时，先看串口输出，再检查接线和电源。

---

## 硬件

本例程不需要外接电路。

| 硬件 | 说明 |
|------|------|
| ESP32-S3 开发板 | 通过 USB 与电脑通信 |
| USB 数据线 | 必须能传数据，不能只用充电线 |
| 电脑 | Windows、macOS 或 Linux 均可 |

---

## 使用步骤

### 1. 上传代码

1. 打开 `02_serial_print.ino`。
2. 选择正确的 ESP32-S3 板卡和端口。
3. 上传程序，等待 Arduino IDE 显示 `Done uploading`。

### 2. 打开串口监视器

可通过以下任一方式打开：

| 方法 | 操作 |
|------|------|
| 菜单 | `Tools` -> `Serial Monitor` |
| 快捷键 | Windows 使用 `Ctrl + Shift + M`，macOS 使用 `Cmd + Shift + M` |
| 图标 | 点击 Arduino IDE 右上角的串口监视器图标 |

### 3. 设置波特率

串口监视器右下角选择：

```text
115200 baud
```

这个值必须和代码中的 `Serial.begin(115200)` 一致。两边波特率不同，通常会看到乱码。

---

## 预期现象

打开串口监视器后，可以看到类似输出：

```text
ESP32-S3 Serial Test Start
millis = 1003
millis = 2004
millis = 3005
millis = 4006
...
```

说明：

| 输出 | 含义 |
|------|------|
| `ESP32-S3 Serial Test Start` | 程序启动时输出一次 |
| `millis = 1003` | 开机后运行了约 1003 毫秒 |
| 数字每秒增加约 1000 | `loop()` 中每次输出后执行了 `delay(1000)` |

数字不一定正好是 1000、2000、3000，因为串口输出和程序执行本身也需要时间。

## 常见问题

### 没有输出

按顺序检查：

1. 串口监视器是否打开的是当前开发板对应的端口。
2. `USB CDC On Boot` 是否设置为 `Enabled`。
3. 上传后是否按过开发板的 EN 或 RST 复位键。
4. USB 数据线是否支持数据传输。
5. 串口是否被其他软件占用。

### 输出乱码

1. 串口监视器波特率设置为 `115200`。
2. 代码中保持 `Serial.begin(115200)`。
3. 修改后重新上传并复位开发板。

### 只显示启动信息，不继续输出

检查 `loop()` 中是否保留了下面两行：

```cpp
Serial.println(millis());
delay(1000);
```

## 代码要点

### 初始化串口

```cpp
Serial.begin(115200);
```

这行代码设置 USB 串口通信速度。串口监视器必须选择相同的速度。

### 输出文本和变量

```cpp
Serial.print("millis = ");
Serial.println(millis());
```

`Serial.print()` 输出后不换行，`Serial.println()` 输出后换行。两者配合使用，可以把提示文字和变量放在同一行。

### 获取运行时间

```cpp
millis()
```

`millis()` 返回开发板从上电或复位到当前经过的毫秒数。它常用于计时、周期任务和非阻塞程序设计。

### 延时

```cpp
delay(1000);
```

`delay(1000)` 表示暂停 1000 毫秒，即 1 秒。本例程用它让串口每秒输出一次。后续涉及网页和多任务控制时，应更多使用 `millis()`，避免长时间阻塞。
